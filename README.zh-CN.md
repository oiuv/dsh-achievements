## 安装

需要 DSH `0.1.7-rc.2`、Web profile，以及 Node `^22.19.0 || >=24`。DSH API 尚未稳定，其他版本需另行验证。

### 从 DSH 源码仓库运行

先按 DSH 的源码运行说明完成依赖安装和构建。以下命令都在 **deepseek-harness 仓库根目录**执行，不要切换到插件目录。已有 `dsh-achievements` 目录时跳过克隆。

```sh
git clone https://github.com/oiuv/dsh-achievements.git
pnpm dsh plugin --profile web add ./dsh-achievements
pnpm dsh web
```

`pnpm dsh web` 是 `pnpm dsh --profile web` 的简写，两者启动同一个 Web profile。`pnpm` 用于运行 DSH 仓库中的启动器，不会选择另一套 profile。执行这两种命令时都应位于 DSH 仓库根目录。

如果使用 Release 安装包，将其下载到 DSH 仓库根目录后运行：

```sh
pnpm dsh plugin --profile web add ./local-dsh-achievements-0.2.0.tgz
pnpm dsh web
```

插件源码也可以放在 DSH 仓库外，在 `add` 后填写对应路径即可。仅把文件夹放入仓库不会自动启用插件；安装记录归属于 `$DSH_HOME/profiles/web/`。

### 使用全局安装的 DSH CLI

如果已经安装全局 CLI，且 PATH 中可以找到 `dsh`，则省略 `pnpm`。在包含插件目录的位置运行：

```sh
dsh plugin --profile web add ./dsh-achievements
dsh web
```

已运行的 DSH 需要重启 Host 并刷新网页。在侧栏点击**成就**。殿堂使用当前 DSH 主题，显示等级进度、图形成就徽章、工具调用条形图和小时活跃分布。

仓库包含构建好的 `client.js`，安装无需执行构建脚本。package.json 和 cordis.patch.yml 中的包名 `@local/dsh-achievements` 必须保持一致。源码运行时，在 DSH 仓库根目录用 `pnpm dsh plugin --profile web remove @local/dsh-achievements` 卸载；使用全局 CLI 时省略 `pnpm`。

## 统计与成就规则

- 手动追加的用户消息决定活跃日期和小时分布。工具消息、替换消息和子代理提示不计入手动活跃。有开发、研究或交付的活跃日期，要求当天既有手动消息，也有对应工作记录。
- 输出 Token 累计已记录的 `assistant/message.usage.outputTokens`。缺失用量不估算，界面显示缺失消息数；它不代表全部 Token 消耗或账单，不包含输入 Token、失败尝试和供应商内部重试。
- 主会话与子代理会话分别计数，均要求存在自身已结束的步骤；工作总量包含双方。分叉继承的历史前缀不重复累计，步骤结束不等于开发任务完成。
- 普通调用与 PTC 子调用均计入工具使用，外层 `run_code` 单独算一次调用。PTC 程序挑战要求至少一个子调用，所有已开始的子调用均结束且无错误标记，外层程序也无错误标记。
- 工具调用与非错误返回分开统计。shell 命令退出码非零仍可能属于非错误工具返回，开发流程或无错误程序均不代表测试通过或产物质量达标。
- 有序的开发和研究组合在正常结束的一轮中最多计一次，不再按整个会话限制次数。同一轮重复操作不加次数，后续正常结束的轮次可继续累计；取消、阻塞和失败轮次不计入完成轮次挑战。
- 规划要求先记录未完成待办，再调用至少五次其他工具。清单完成要求至少三项，且内容与顺序保持不变；插件只保留内容摘要，不保存正文。整份清单的重复快照不会被累计为新任务。
- 文件交付以非空 `deliverables/presented` 事件为准，按会话内调用 ID 去重。同一文件反复展示属于多次交付记录，不是多个独立作品。覆盖会话的挑战只统计发生过相关行为的主会话。
- 标准子代理入口包括 `subagent`、`subagent_fork`、`subagent_codex` 和 `subagent_claude_code`。协作交付需要父会话的子代理关联记录，以及按日志时间在父轮次内、交付前完成的子代理响应；仅启动后台子代理不计入协作交付。
- 工作流须有配对的开始、结束记录，且结束原因是完成；成员挑战还要求所有记录的成员完成，阶段挑战只计具名阶段。失败恢复要求在失败运行结束后重新启动同名工作流。目标按完成的目标 ID 计数，这些是生命周期记录，不是独立质量评估。
- 终端挑战核对同一个终端 ID 的发送→读取→关闭流程。能力类别识别官方工具名；任意改名仍计入使用总量，但不推断其能力归属。专项挑战需要启用对应 DSH 工具。
- 历史导入不连续弹出解锁提示。解锁日期记录检测时间，不回溯原始达成日期。当前格式的统计在重启和源日志删除后保留；日历按配置时区计算，更换时区需要新的数据库。

数据在会话写入磁盘及轮询后更新，不跟随每个流式片段即时变化。部分历史无法读取时显示导入不完整，并提供重试。插件没有远程分析、对话上传或模型工具。

## 成就与等级

72 项公开成就由 24 项核心挑战、47 项专项挑战和 1 项白金组成。解锁 24 项核心成就即可获得白金，专项、隐藏挑战和成就升级不影响白金。图鉴支持按功能路线、难度、分册和解锁状态筛选。专项涵盖 PTC 组合、子代理响应、工作流成员与阶段、Skill、终端、语义工具、浏览器及 MCP 资源。

入门成就引导首次真实使用，进阶和精通成就要求组合能力与多次实践；传说挑战包括八名子代理协作、多阶段工作流、千轮开发流程及 365 个活跃日期。9 项隐藏挑战在解锁前不展示名称和具体条件。

仅 19 项明确标注的累计型成就可升级。达到基础目标为 Lv. 1，此后累计值每翻倍升一级。例如已记录输出 Token 成就在 100 万达到 Lv. 1、200 万达到 Lv. 2、400 万达到 Lv. 3，并显示下一级目标 800 万。等级由持久化累计值计算，重放或重启不会丢失。首次体验、单次记录、能力种类、连续天数、隐藏成就及白金不升级。

玩家等级与成就等级独立。XP 仅在首次解锁时奖励，成就升级不重复发放玩家 XP，也不增加已解锁数量。完成两项核心入门挑战即可达到玩家等级 2；不解锁隐藏成就也能达到最高玩家等级。

## 配置与数据

默认数据库为 `$DSH_HOME/achievements/stats.sqlite`，使用系统时区。在 profile 的 `cordis.patch.yml` 中覆盖完整配置：

```yaml
- id: dsh-achievements
  config:
    database: !!js dshHomePath('achievements', 'stats.sqlite')
    timeZone: Asia/Shanghai
    pollMs: 3000
    pageSize: 512
    busyTimeoutMs: 5000
```

数据库必须使用绝对路径；轮询至少 1000 毫秒；每页 1–4096 条事件；SQLite 等待超时为 1–30000 毫秒。IANA 时区名称在加载时验证。共享会话历史的 profile 应使用同一数据库。

SQLite 保存计数、读取位置、日期、轮次时间、工具与 Skill 标识、清单和终端的摘要标识、目标与工作流 ID，以及父子会话关联。不复制提示词、回复、文件路径、命令正文或工具结果正文。仪表盘接口经过 DSH 连接层认证，卸载时先等待读取关闭，再关闭数据库。

当前统计格式为 v2。打开开发期 v1 数据库时会清空计数、读取位置及解锁，再导入仍可读取的会话日志；已删除的源日志无法重建。升级前应停止所有使用该数据库的 Host。手动重建时同样先停止 Host，仅删除插件统计文件后重启。插件不会修改 DSH 会话日志。

## 开发与发布

```sh
npm ci
npm test
npm run build
npm run check
npm pack
```

界面源码为 `src/client.js`、`src/client.css` 和双语字典；`src/catalog.js` 管理成就条件和经验。提交源码时同步提交生成的 `client.js`。构建显式设置编译选项，不继承父目录的 tsconfig。CI 在 Windows、Linux 的 Node 22.19 和 24 上检查测试、可重复构建及打包。

`src/events.js` 处理普通调用、PTC 和领域事件；`src/engine.js` 负责汇总、读取位置和解锁的事务持久化，`src/collector.js` 负责历史读取与取消。测试覆盖重放、失败和未配对结果、子代理关联、升级阈值、数据库重置及卸载；提交的 PTC 样例保留了 DSH `ptc-node-workspace` 录制中的相关持久化事件。插件不增加模型输入或修改 DSH 持久化格式，统计状态和读取位置在同一个 SQLite 事务内提交。

将本目录作为独立仓库发布，并把生成的 tarball 附加到 Release。不要提交统计数据库、DSH home、node_modules 或本地测试输出。采用 [MIT 许可证](LICENSE)。
